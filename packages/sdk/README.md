# @edgway/sdk

The Edgway admin API (`/api/v1`) as a typed client, TanStack Query v5 options and zod schemas. It is generated by [`@hey-api/openapi-ts`](https://heyapi.dev) (pinned) from the admin's OpenAPI document, `apps/admin/openapi.json`. Everything under `src/generated` is generator output and is never edited by hand.

```ts
import { createEdgwayClient, listServices } from "@edgway/sdk";

const client = createEdgwayClient({
  adminUrl: "https://admin.example.com",
  // A Cloudflare Access service token (the admin sits behind Access).
  headers: {
    "CF-Access-Client-Id": process.env.CF_ACCESS_CLIENT_ID!,
    "CF-Access-Client-Secret": process.env.CF_ACCESS_CLIENT_SECRET!,
  },
});
const { data } = await listServices({ client });
```

`adminUrl` is the admin's origin: the API path (`/api/v1`, from the document's `servers`) replaces any path in it, so an admin served under a path prefix needs its own `baseUrl`.

The TanStack Query helpers (`listServicesOptions`, `createServicesMutation`, …) need `@tanstack/react-query` v5, an optional peer dependency. Responses are validated with the generated zod schemas.

## Regenerating

After the admin API changes:

```sh
pnpm --filter @edgway/admin openapi   # writes apps/admin/openapi.json
pnpm --filter @edgway/sdk generate    # rewrites src/generated
```

The admin's tests (`apps/admin/test/api.test.ts`) fail when the committed `openapi.json` differs from what the Worker serves. To catch SDK drift, run `pnpm --filter @edgway/sdk generate && git diff --exit-code packages/sdk/src` (the task's acceptance check).
