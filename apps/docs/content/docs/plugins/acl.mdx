Edgway accepts Kong's `acl` configuration unchanged: the schema below is Kong's own. The plugin package's [README](https://github.com/scoobydrew83/edgway/blob/main/plugins/acl/README.md) lists what Edgway doesn't support.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `config.allow` | array of string |  |  | Arbitrary group names that are allowed to consume the service or route. One of `config.allow` or `config.deny` must be specified. |
| `config.always_use_authenticated_groups` | boolean |  | `false` | If enabled (`true`), the authenticated groups will always be used even when an authenticated consumer already exists. If the authenticated groups don't exist, it will fallback to use the groups associated with the consumer. By default the authenticated groups will only be used when there is no consumer or the consumer is anonymous. |
| `config.deny` | array of string |  |  | Arbitrary group names that are not allowed to consume the service or route. One of `config.allow` or `config.deny` must be specified. |
| `config.hide_groups_header` | boolean |  | `false` | If enabled (`true`), prevents the `X-Consumer-Groups` header from being sent in the request to the upstream service. |
| `config.include_consumer_groups` | boolean |  | `false` | If enabled (`true`), allows the consumer-groups to be used in the `allow\|deny` fields |
