Edgway accepts Kong's `rate-limiting` configuration unchanged: the schema below is Kong's own. The plugin package's [README](https://github.com/scoobydrew83/edgway/blob/main/plugins/rate-limiting/README.md) lists what Edgway doesn't support.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `config.day` | number |  |  | The number of HTTP requests that can be made per day. |
| `config.error_code` | number |  | `429` | Set a custom error code to return when the rate limit is exceeded. |
| `config.error_message` | string |  | `"API rate limit exceeded"` | Set a custom error message to return when the rate limit is exceeded. |
| `config.fault_tolerant` | boolean |  | `true` | A boolean value that determines if the requests should be proxied even if Kong has troubles connecting a third-party data store. If `true`, requests will be proxied anyway, effectively disabling the rate-limiting function until the data store is working again. If `false`, then the clients will see `500` errors. |
| `config.header_name` | string |  |  | A string representing an HTTP header name. |
| `config.hide_client_headers` | boolean |  | `false` | Optionally hide informative response headers. |
| `config.hour` | number |  |  | The number of HTTP requests that can be made per hour. |
| `config.limit_by` | `"consumer"`, `"consumer-group"`, `"credential"`, `"header"`, `"ip"`, `"path"`, `"service"` |  | `"consumer"` | The entity that is used when aggregating the limits. |
| `config.minute` | number |  |  | The number of HTTP requests that can be made per minute. |
| `config.month` | number |  |  | The number of HTTP requests that can be made per month. |
| `config.path` | string |  |  | A string representing a URL path, such as /path/to/resource. Must start with a forward slash (/) and must not contain empty segments (i.e., two consecutive forward slashes). |
| `config.policy` | `"cluster"`, `"local"`, `"redis"` |  | `"local"` | The rate-limiting policies to use for retrieving and incrementing the limits. |
| `config.redis` | object |  |  | Redis configuration |
| `config.redis.database` | integer |  | `0` | Database to use for the Redis connection when using the `redis` strategy |
| `config.redis.host` | string |  |  | A string representing a host name, such as example.com. |
| `config.redis.password` | string |  |  | Password to use for Redis connections. If undefined, no AUTH commands are sent to Redis. This field is [encrypted](https://developer.konghq.com/gateway/keyring/). This field is [referenceable](https://developer.konghq.com/gateway/entities/vault/#how-do-i-reference-secrets-stored-in-a-vault). |
| `config.redis.port` | integer |  | `6379` | An integer representing a port number between 0 and 65535, inclusive. |
| `config.redis.server_name` | string |  |  | A string representing an SNI (server name indication) value for TLS. |
| `config.redis.ssl` | boolean |  | `false` | If set to true, uses SSL to connect to Redis. |
| `config.redis.ssl_verify` | boolean |  | `false` | If set to true, verifies the validity of the server SSL certificate. If setting this parameter, also configure `lua_ssl_trusted_certificate` in `kong.conf` to specify the CA (or server) certificate used by your Redis server. You may also need to configure `lua_ssl_verify_depth` accordingly. |
| `config.redis.timeout` | integer |  | `2000` | An integer representing a timeout in milliseconds. Must be between 0 and 2^31-2. |
| `config.redis.username` | string |  |  | Username to use for Redis connections. If undefined, ACL authentication won't be performed. This requires Redis v6.0.0+. To be compatible with Redis v5.x.y, you can set it to `default`. This field is [referenceable](https://developer.konghq.com/gateway/entities/vault/#how-do-i-reference-secrets-stored-in-a-vault). |
| `config.second` | number |  |  | The number of HTTP requests that can be made per second. |
| `config.sync_rate` | number |  | `-1` | How often to sync counter data to the central data store. A value of -1 results in synchronous behavior. |
| `config.year` | number |  |  | The number of HTTP requests that can be made per year. |
