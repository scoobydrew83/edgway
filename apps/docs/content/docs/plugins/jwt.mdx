Edgway accepts Kong's `jwt` configuration unchanged: the schema below is Kong's own. The plugin package's [README](https://github.com/scoobydrew83/edgway/blob/main/plugins/jwt/README.md) lists what Edgway doesn't support.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `config.anonymous` | string |  |  | An optional string (consumer UUID or username) value to use as an “anonymous” consumer if authentication fails. |
| `config.claims_to_verify` | array of `"exp"`, `"nbf"` |  |  | A list of registered claims (according to RFC 7519) that Kong can verify as well. Accepted values: one of exp or nbf. |
| `config.cookie_names` | array of string |  | `[]` | A list of cookie names that Kong will inspect to retrieve JWTs. |
| `config.header_names` | array of string |  | `["authorization"]` | A list of HTTP header names that Kong will inspect to retrieve JWTs. |
| `config.key_claim_name` | string |  | `"iss"` | The name of the claim in which the key identifying the secret must be passed. The plugin will attempt to read this claim from the JWT payload and the header, in that order. |
| `config.maximum_expiration` | number |  | `0` | A value between 0 and 31536000 (365 days) limiting the lifetime of the JWT to maximum_expiration seconds in the future. |
| `config.realm` | string |  |  | When authentication fails the plugin sends `WWW-Authenticate` header with `realm` attribute value. |
| `config.run_on_preflight` | boolean |  | `true` | A boolean value that indicates whether the plugin should run (and try to authenticate) on OPTIONS preflight requests. If set to false, then OPTIONS requests will always be allowed. |
| `config.secret_is_base64` | boolean |  | `false` | If true, the plugin assumes the credential’s secret to be base64 encoded. You will need to create a base64-encoded secret for your Consumer, and sign your JWT with the original secret. |
| `config.uri_param_names` | array of string |  | `["jwt"]` | A list of querystring parameters that Kong will inspect to retrieve JWTs. |
