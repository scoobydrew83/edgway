Edgway accepts Kong's `key-auth` configuration unchanged: the schema below is Kong's own. The plugin package's [README](https://github.com/scoobydrew83/edgway/blob/main/plugins/key-auth/README.md) lists what Edgway doesn't support.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `config.anonymous` | string |  |  | An optional string (consumer UUID or username) value to use as an “anonymous” consumer if authentication fails. If empty (default null), the request will fail with an authentication failure `4xx`. |
| `config.hide_credentials` | boolean |  | `false` | An optional boolean value telling the plugin to show or hide the credential from the upstream service. If `true`, the plugin strips the credential from the request. |
| `config.key_in_body` | boolean |  | `false` | If enabled, the plugin reads the request body. Supported MIME types: `application/www-form-urlencoded`, `application/json`, and `multipart/form-data`. |
| `config.key_in_header` | boolean |  | `true` | If enabled (default), the plugin reads the request header and tries to find the key in it. |
| `config.key_in_query` | boolean |  | `true` | If enabled (default), the plugin reads the query parameter in the request and tries to find the key in it. |
| `config.key_names` | array of string |  | `["apikey"]` | Describes an array of parameter names where the plugin will look for a key. The key names may only contain [a-z], [A-Z], [0-9], [_] underscore, and [-] hyphen. |
| `config.realm` | string |  |  | When authentication fails the plugin sends `WWW-Authenticate` header with `realm` attribute value. |
| `config.run_on_preflight` | boolean |  | `true` | A boolean value that indicates whether the plugin should run (and try to authenticate) on `OPTIONS` preflight requests. If set to `false`, then `OPTIONS` requests are always allowed. |
