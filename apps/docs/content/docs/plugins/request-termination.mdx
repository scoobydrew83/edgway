Edgway accepts Kong's `request-termination` configuration unchanged: the schema below is Kong's own. The plugin package's [README](https://github.com/scoobydrew83/edgway/blob/main/plugins/request-termination/README.md) lists what Edgway doesn't support.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `config.body` | string |  |  | The raw response body to send. This is mutually exclusive with the `config.message` field. |
| `config.content_type` | string |  |  | Content type of the raw response configured with `config.body`. |
| `config.echo` | boolean |  | `false` | When set, the plugin will echo a copy of the request back to the client. The main usecase for this is debugging. It can be combined with `trigger` in order to debug requests on live systems without disturbing real traffic. |
| `config.message` | string |  |  | The message to send, if using the default response generator. |
| `config.status_code` | integer |  | `503` | The response code to send. Must be an integer between 100 and 599. |
| `config.trigger` | string |  |  | A string representing an HTTP header name. |
