Edgway accepts Kong's `request-size-limiting` configuration unchanged: the schema below is Kong's own. The plugin package's [README](https://github.com/scoobydrew83/edgway/blob/main/plugins/request-size-limiting/README.md) lists what Edgway doesn't support.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `config.allowed_payload_size` | integer |  | `128` | Allowed request payload size in megabytes. Default is `128` megabytes (128000000 bytes). |
| `config.require_content_length` | boolean |  | `false` | Set to `true` to ensure a valid `Content-Length` header exists before reading the request body. |
| `config.size_unit` | `"bytes"`, `"kilobytes"`, `"megabytes"` |  | `"megabytes"` | Size unit can be set either in `bytes`, `kilobytes`, or `megabytes` (default). This configuration is not available in versions prior to Kong Gateway 1.3 and Kong Gateway (OSS) 2.0. |
