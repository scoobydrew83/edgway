Edgway accepts Kong's `proxy-cache` configuration unchanged: the schema below is Kong's own. The plugin package's [README](https://github.com/scoobydrew83/edgway/blob/main/plugins/proxy-cache/README.md) lists what Edgway doesn't support.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `config.cache_control` | boolean |  | `false` | When enabled, respect the Cache-Control behaviors defined in RFC7234. |
| `config.cache_ttl` | integer |  | `300` | TTL, in seconds, of cache entities. |
| `config.content_type` | array of string |  | `["application/json","text/plain"]` | Upstream response content types considered cacheable. The plugin performs an **exact match** against each specified value. |
| `config.ignore_uri_case` | boolean |  | `false` |  |
| `config.memory` | object |  |  |  |
| `config.memory.dictionary_name` | string |  | `"kong_db_cache"` | The name of the shared dictionary in which to hold cache entities when the memory strategy is selected. Note that this dictionary currently must be defined manually in the Kong Nginx template. |
| `config.request_method` | array of `"GET"`, `"HEAD"`, `"PATCH"`, `"POST"`, `"PUT"` |  | `["GET","HEAD"]` | Downstream request methods considered cacheable. |
| `config.response_code` | array of integer |  | `[200,301,404]` | Upstream response status code considered cacheable. |
| `config.response_headers` | object |  |  | Caching related diagnostic headers that should be included in cached responses |
| `config.response_headers.age` | boolean |  | `true` |  |
| `config.response_headers.X-Cache-Key` | boolean |  | `true` |  |
| `config.response_headers.X-Cache-Status` | boolean |  | `true` |  |
| `config.storage_ttl` | integer |  |  | Number of seconds to keep resources in the storage backend. This value is independent of `cache_ttl` or resource TTLs defined by Cache-Control behaviors. |
| `config.strategy` | `"memory"` | yes |  | The backing data store in which to hold cache entities. |
| `config.vary_headers` | array of string |  |  | Relevant headers considered for the cache key. If undefined, none of the headers are taken into consideration. |
| `config.vary_query_params` | array of string |  |  | Relevant query parameters considered for the cache key. If undefined, all params are taken into consideration. |
